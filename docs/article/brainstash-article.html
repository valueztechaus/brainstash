At 11:39 on a Wednesday morning I typed a single message into Claude Code. I asked for an iOS app to capture the product, service and problem ideas that come to me at odd times, so I could review them later and pick up the ones worth building. I asked for it to be designed first, built in Flutter, tested in the iOS simulator, secured and security-tested with standard tools, documented, ready for the App Store, and released as a public GitHub project. I also said: do it in one shot, use your best judgement, and record every decision.

At 12:26 the first version was running in the simulator. By 16:14 it was running on my own iPhone with voice capture, hands-free saving, voice search and photo and file attachments. The whole thing is open source at github.com/valueztechaus/brainstash.

I want to share what actually happened, including the parts that were not automatic, because I believe this changes what Valueztech can offer our clients.

What was built

Brainstash is a small app, but it is not a demo. It has the things I would expect from a production mobile app delivered to a client:

  • Encryption at rest with AES-256. The key is generated on the device and kept in the iOS Keychain, never synced to iCloud. Ideas and attachments are excluded from backups.
  • Optional Face ID lock, with re-authentication before export or delete-all, and a privacy cover in the app switcher.
  • No network at all. No accounts, no analytics, no crash reporting. Speech recognition is forced on-device.
  • 95 automated tests, including tests that read the raw database file to prove nothing is stored in plain text, and an integration test on the simulator that also produced the App Store screenshots.
  • Security testing on every change with gitleaks (secrets), osv-scanner (dependency CVEs), semgrep (static analysis) and MobSF (mobile app scan of the built binary). All clean, and they run in GitHub Actions on every push.
  • 40 recorded decisions, each with the reason and the alternative that was rejected. A design spec, an implementation plan, a security report and an App Store submission checklist.

What was not automatic

I don't want to oversell this. A few things still needed me.

Installing Xcode and Apple developer account steps. Accepting Apple's updated agreement, choosing the signing team and plugging in the phone are things only the account owner can do. Claude told me exactly what to click each time, but I had to click it.

One confusing moment. After the automated simulator test, the build left on the simulator was the test build, so taps did not work. It took one message to find and fix, and a note was added to the README so others don't hit it.

One oversight. The independent security review ran on a smaller model than the one I asked for, because that reviewer agent had its own default. Its findings were checked and fixed, and the slip is recorded openly in the decision log.

Judgement still matters. The quality came from the brief: security, testing, documentation and an open record of decisions were in the first message. If you don't ask for them, you are less likely to get them.
